# Loop runbook — Implement the academic-research-plugin DSH profile from its frozen planning docs (README/PRINCIPLES/ARCHITECTURE/EVIDENCE-ENGINE/ORCHESTRATION/TESTING) into a runnable, TUI/headless profile whose product is credibility: every claim carries a machine-decided verified/unverified state. Build sequentially by module M1-M8 with a deterministic gate + fresh adversarial attack + fix-audit at each stage, and the gated-vs-freehand + hyper-parallel-vs-serial A/B honest test as milestone 1 that green-lights the expensive scale-up.

> ⛔ **DO NOT AUTO-START.** This runbook is a DESIGN artifact only. Implementation
> has not begun. Start it deliberately, from the `skeleton` stage, only when the
> operator chooses to. Before iteration 1: (a) freeze the planning docs as the
> contract source; (b) as the build's OWN first act, discharge the M0 debts recorded
> in README (upgrade every `[E:]` pointer to `path#anchor + frozen hash`; schedule the
> hyper-parallel-vs-serial A/B into milestone 1 — already wired as arm B here); (c)
> re-run an independent fix-audit on the R2 planning-doc diff (ATTACK-LEDGER records it
> as the one un-audited change). Run everything via `dsh --profile` / exit codes — TUI
> only, never the WebUI.

> A runnable closed-loop design generated by loop-constructor. Follow it as a loop: make a small change → run the stage check → read the result → fix → repeat until the check passes, then advance.
> **Altitude:** medium — The PRODUCT is hyper-parallel multi-loop, but BUILDING it is strictly sequential: each module consumes the prior module's frozen contract on one shared build surface, so parallel construction would conflict-edit (P-11). Single-agent gated stages, no build-time fan-out — matches both house pipelines (plugin-creator/serper-harvester) which are medium with deliberate zero internal fan-out. Fan-out lives inside the built product's runtime, not inside its construction loop.

## Hard constraints
- Minimal viable change; don't touch unrelated files.
- Don't change public APIs / add deps without justification.
- No production resources.
- On a requirement contradiction → STOP and report.

## Roles (three separate contexts — never one agent grading itself)
- **Planner:** Fable conductor: read the frozen planning docs -&gt; per-stage spec + the negotiated contract assertions; never writes plugin/gate/preset code. Resolves the docs as the frozen contract source (README/PRINCIPLES/ARCHITECTURE/EVIDENCE-ENGINE/ORCHESTRATION/TESTING), not its own memory.
- **Generator:** Opus subagents: write the plugin/gates/preset/checks to satisfy the contract; may NOT weaken a check, edit checks/ or .loop-state/, or grade their own output. Negative tests must be red-before-green with the RED evidence committed.
- **Evaluator (fresh context, adversarial — told the artifact is broken, proves it):** a FRESH context that never saw the impl or the generator's reasoning; assume the credibility machinery is broken and prove it — forge a snapshot, bypass the gateway, launder an unverified claim into verified via a constant transform or a self-reviewed rescue, game the head metric denominator, break burned-task isolation. Different-vendor attacker on the high-stakes stages buys model-tier independence. A fixer never audits its own fix (fix-audit rotation).

## Contract (negotiated acceptance criteria — grade THIS, not the original spec)
> The generator and evaluator agreed these testable assertions before the build. The loop is done only when every one is proven by its check.
- **`A1`** (stage `skeleton`) — the profile boots headless and exits 0 on a no-op task · graded by `dsh --profile academic-research 'noop; exit'; test $? -eq 0`
- **`A2`** (stage `skeleton`) — a real boot with a fake API key dies at AUTH, not at the cordis plugin-loader, and every plugin exports a valid Config · graded by `DEEPSEEK_API_KEY=sk-fake dsh --profile academic-research 'x' 2>&1 | grep Authentication`
- **`A3`** (stage `evidence-contracts`) — all 27 EVIDENCE-ENGINE §6 negative fixtures are tool-triggered and each is RED-before-green then rejected by the fixed gate · graded by `node checks/gates_selftest.mjs --fixtures 27 --require-all-red-then-green`
- **`A4`** (stage `evidence-contracts`) — the claims.tsv status column is physically written ONLY by the gate script; admission writes new rows at status=pending; a worker/conductor write attempt to status is observably rejected and the column is unchanged · graded by `node checks/write_authority.mjs --attempt-worker-write --expect-rejected --assert-status-unchanged`
- **`A5`** (stage `evidence-contracts`) — a constant transform and an epsilon-dependency transform both FAIL the data input-dependency gate, while a genuinely input-dependent transform PASSES (the trichotomy) · graded by `node checks/input_dependency.mjs --constant FAIL --epsilon FAIL --real PASS`
- **`A6`** (stage `evidence-contracts`) — reviewer!=producer is enforced from the harness childId in session events, not a self-reported manifest field; a verdict whose reviewer childId equals the producer childId cannot write a terminal state · graded by `node checks/reviewer_independence.mjs --same-childid --expect-no-terminal`
- **`A7`** (stage `evidence-contracts`) — load-bearing is machine-decided: a claim that is prose-cited OR an inference premise OR on a conclusion chain is immutably load-bearing; an author 'non-load-bearing' mark on such a claim is rejected · graded by `node checks/load_bearing.mjs --mark-prose-cited-nonbearing --expect-rejected`
- **`A8`** (stage `evidence-contracts`) — an inference whose conclusion is stronger than its steps support is caught by the reviewer's conclusion-strength question · graded by `node checks/inference_strength.mjs --overclaim --expect-flagged`
- **`A9`** (stage `evidence-contracts`) — the fail-closed selftest includes a missing-panel negative case proving a missing eval dimension cannot yield SHIP · graded by `node checks/gates_selftest.mjs -t missing-panel-cannot-ship`
- **`A10`** (stage `academic-search`) — every manifest.snapshot_hash binds to a real tool RESULT event hash in the session jsonl; a tampered CAS snapshot fails anti-forgery · graded by `node checks/antiforgery_probe.mjs --tamper-snapshot --expect-fail`
- **`A11`** (stage `academic-search`) — a fabricated URL not present in any tool RESULT event fails the anti-forgery gate · graded by `node checks/antiforgery_probe.mjs --fabricate-url --expect-fail`
- **`A12`** (stage `academic-search`) — evidence fetched by bypassing the gateway tool (direct bash+curl, no RESULT event) is rejected as unbindable · graded by `node checks/antiforgery_probe.mjs --bypass-gateway --expect-fail`
- **`A13`** (stage `academic-search`) — a load-bearing source claim requires &gt;=2 independent-publisher sources; a two-preprint combo gets a preprint-only flag and verified-by-source is downgraded · graded by `node checks/source_independence.mjs --two-preprints --expect-flag-and-downgrade`
- **`A14`** (stage `academic-search`) — the retraction / hijacked-journal L0 join runs offline and default-on; citing retracted work raises a flag · graded by `node checks/source_integrity_l0.mjs --cite-retracted --expect-flag`
- **`A15`** (stage `academic-search`) — the pure lib/ has zero @deepseek-ai imports and its unit tests pass standalone · graded by `grep -rL '@deepseek-ai' dsh-academic-search/lib && npm --prefix dsh-academic-search test`
- **`A16`** (stage `research-preset-min`) — a headless run produces a claim ledger with &gt;=1 claim per kind (data/source/inference) reaching a POSITIVE terminal state written only by the gate · graded by `node checks/assert_terminal_states.mjs --kinds data,source,inference --writer gate-only --require-positive`
- **`A17`** (stage `milestone-1-ab`) — the milestone-1 A/B runs BOTH arms (gated:freehand and parallel:serial-same-budget) to completion on held-out tasks and populates the scoreboard · graded by `node eval/harness.mjs --ab gated:freehand --ab parallel:serial-same-budget --held-out`
- **`A18`** (stage `milestone-1-ab`) — every scoreboard success number is paired with an integrity/damage metric (unpaired success is rejected) and a held-out task that entered any dev loop is never re-scored · graded by `node checks/scoreboard_integrity.mjs --require-paired-metrics --require-burned-task-isolation`
- **`A19`** (stage `milestone-1-ab`) — the head metric denominator is the ledger load-bearing set UNION the prose (measured held-out side), never the L1 pass-rate; a prose that narrates only verified claims cannot inflate it · graded by `node checks/head_metric_denominator.mjs --curate-prose --expect-no-inflation`
- **`A20`** (stage `hardening-scale`) — eval-of-eval: a planted confident-but-wrong candidate is forced to REVISE and a missing-panel candidate cannot SHIP · graded by `node eval/selftest.mjs --plant confident-but-wrong --expect REVISE --plant missing-panel --expect NOT-SHIP`
- **`A21`** (stage `hardening-scale`) — 8 concurrent grounders do not corrupt the ledger (admission single-instance lock + content-hash keys) · graded by `node checks/concurrent_admission.mjs --grounders 8 --assert-no-corruption`
- **`A22`** (stage `hardening-scale`) — citation-support-rate stays flat as tool-calls scale 2-&gt;20-&gt;150 (parallelism does not amplify sourcing error), and the achieved tool-call count reached each target · graded by `node checks/parallel_regression.mjs --toolcalls 2,20,150 --assert-support-rate-flat --assert-achieved`
- **`A23`** (stage `attack-fixaudit`) — the attack battery is seed-verified (planted seeds hit, blind runs voided) and a fresh-context fix-audit returns CONVERGED with zero open P1/P2 · graded by `node checks/attack_battery.mjs --require-seed-hit --cross-vendor && node checks/fixaudit.mjs --fresh-context --require-verdict CONVERGED`
- **`A24`** (stage `prose-exit-bench`) — the prose exit emits only ledger-backed empirical sentences (each cites a claim_id and surfaces its true state), zero ledger-external assertions · graded by `node checks/prose_exit_closure.mjs --assert-sentences-subset-of-ledger`
- **`A25`** (stage `cross-cutting`) — no gate/test/check assertion is weakened relative to its gates-baseline tag over the whole build · graded by `human-verify: the evaluator diffs checks/ and gates/ against each gates-baseline-<stage> tag and confirms no assertion was loosened (includes untracked files via git status --porcelain)`
- **`A26`** (stage `cross-cutting`) — every gate threshold is calibrated on a self-built golden set, never a number copied from the survey/literature (P-21) · graded by `human-verify: the evaluator confirms each numeric threshold traces to a runs/_calib golden artifact, not a SURVEY citation`
- **`A27`** (stage `cross-cutting`) — all runtime/debug/verification surfaces are TUI/headless (dsh --profile, exit codes); no gate or acceptance step depends on the WebUI · graded by `grep -rL 'web-app\|WebUI\|--port' checks/ && node checks/headless_only.mjs`

## Why this shape (decision log)
> The D0–D6 selection procedure that derived this loop's shape.
- **D0** (loop) — every stage has a fast runnable done-check: headless `dsh --profile academic-research &lt;task&gt;` exit code, real-boot-with-fake-key gate, the 27 negative fixtures asserting rejection, gate-script exit codes on runs/_smoke, and the held-out eval harness exit code + scoreboard delta. Done is machine-decidable without a human reading output.
- **D1** (staged (8 seams by module dependency, ARCHITECTURE §4)) — each seam hands a stable checkable artifact downstream and its check runs without the downstream existing: booting profile -&gt; green gates+fixtures -&gt; booting plugin emitting evidence events -&gt; a headless run producing a gate-passing claim ledger -&gt; an A/B scoreboard delta -&gt; a scaled+hardened system -&gt; an attack+fix-audit ledger -&gt; a wrapped+regressed profile. Contract-first (gates before the plugin that feeds them) satisfies seam-test (a): the gate scripts run standalone on _smoke fixtures.
- **D2** (retry / plan_execute_verify / review + human_in_the_loop) — skeleton and prose-exit-bench are mechanical (retry); the credibility core (evidence-contracts, academic-search, research-preset, hardening-scale) is risky and needs mid-flight correction (plan_execute_verify, red-green); milestone-1-ab is a quality judgment on the whole approach (review) with a human go/no-go; attack-fixaudit is adversarial (review).
- **D3** (on_the_loop, except milestone-1-ab = in_the_loop) — dev-only, reversible, discriminating checks -&gt; human reviews at gates. Exception: the A/B honest-test verdict (does hyper-parallel earn its cost, P-15) is a judgment no check can make — the check only proves the A/B RAN honestly with paired metrics; the human owns the go/no-go and a null result is an accepted honest outcome, not a failure to grind against (anti-reward-hacking, P-18).
- **D4** (medium) — stages are strictly sequential (each depends_on the prior); the single build surface makes parallel construction a shared-write conflict. The product's hyper-parallelism is a runtime property of M4, not a property of the build loop.
- **D5** (caps + loopback + pre-registered restart + budget/zero-change/min-progress gates) — per-stage caps; downstream failures loopback to the implicated upstream gate; evidence-contracts and academic-search carry pre-registered restart counters (a build-turned-archaeology is rewritten from the contract, not patched); outer zero-change brake + minimum-progress floor; house budget guard (DeepSeek balance floor + per-stage token cap).
- **D6** (completeness-first (mixed: red-green inner cycle is iteration-first)) — the discriminating checks are slow/expensive (headless dsh runs are minutes-long, real boots, held-out eval, e2e evidence-materialization) and the artifacts reward a coherent whole (contracts, a profile, a migration cutover), so few thorough passes beat many cheap ones -&gt; low caps, plan_execute_verify, thorough checks. The exception is the negative-fixture red-green cycle inside evidence-contracts, which is genuinely iteration-first (fast unit checks) and carries a higher inner cap — recorded per-stage.

## Stages (run in dependency order; each stage is its own gated loop)
> After a stage gate goes green, commit/checkpoint it; on a loopback, reset to the last green checkpoint rather than editing forward.

### Stage 1 — `skeleton`  ·  pattern: retry

- **Done when:** the profile ~/.dsh/profiles/academic-research (package.json dsh.profile.bundles + cordis.patch.yml) boots headless and exits 0 on a no-op task, and a real boot with a deliberately-fake API key dies at AUTH (not at the cordis plugin-loader), proving the bundle graph and every plugin's exported Config are valid
- **Check (run — the gate):** `dsh --profile academic-research --dump-config >/dev/null && DEEPSEEK_API_KEY=sk-fake-000 dsh --profile academic-research 'noop; exit' 2>&1 | grep -q 'Authentication' && echo BOOT_OK`  ·  expect: `pass`
- **Falsifiable when:** dump-config errors, OR the fake-key boot dies with a cordis-plugin-loader / Config-validation error instead of an AUTH error — proving a bundle or an exported Config schema is broken (the house plugin_load.sh lesson: dump-config alone passed a pure stub, only a real boot catches load-time invariants)
- **Passing-but-wrong (ruled out):** a plugin that dump-config accepts but that has no `export const Config = z.object(...)` and would crash at load — ruled out: the fake-key real-boot must reach AUTH, which only happens after every plugin's load-time Config validation passes (@deepseek-ai/cordis runtime.Config.validate)
- **Depends on:** — (entry stage)  ·  admit downstream only once this check passes.
- **Stop:** max 4 iterations; failure branches:
    - 3 consecutive boots fail at plugin-loader with the same Config error (a bundle is structurally wrong, not our task)
- **On failure:** escalate.

### Stage 2 — `evidence-contracts`  ·  pattern: plan_execute_verify

- **Done when:** the credibility core exists and is proven by red-green: claims.tsv 8-col schema + per-claim manifest + CAS; the M3 gate scripts (data 4-layer / source ladder / inference DAG / source-integrity L0-L1); all 27 EVIDENCE-ENGINE §6 negative fixtures are tool-triggered and assert-REJECTED; the fail-closed selftest includes the missing-panel negative case; status is written ONLY by the gate
- **Check (run — the gate):** `node checks/gates_selftest.mjs --fixtures 27 --require-all-red-then-green && python3 gates/run.py runs/_smoke && git diff gates-baseline-evidence -- checks/ gates/ | wc -l | grep -qx 0`  ·  expect: `pass`
- **Falsifiable when:** any of the 27 negative fixtures is NOT rejected when tool-triggered (e.g. a constant/epsilon-dependency transform passes the input-dependency gate; a worker write to the status column is not rejected; a fabricated snapshot passes anti-forgery; reviewer_id==producer_id still writes a terminal state) — a fixture stays green when it must go red
- **Passing-but-wrong (ruled out):** the fixtures 'pass' because they were weakened to vacuous asserts, or because a fixture file exists but is never tool-triggered ('存在即覆盖', banned by P-9) — ruled out: gates_selftest requires each fixture to first FAIL on the un-fixed gate (RED) then be rejected by the fixed gate (GREEN), and the baseline-tag diff proves no check/gate file drifted since the conductor committed it
- **Depends on:** `skeleton`  ·  admit downstream only once this check passes.
- **Stop:** max 12 iterations; failure branches:
    - a fixture that was green goes red again after a fix to a sibling rule (patch-vs-break arms race)
    - the gate scripts cannot be made to reject all 27 fixtures without weakening an assertion
- **On failure:** restart.

### Stage 3 — `academic-search`  ·  pattern: plan_execute_verify

- **Done when:** the M1 dsh-academic-search plugin retrieves via the academic stack + generic-web fallback chain, materializes each snapshot into CAS AT FETCH TIME with the tool executor recording the response sha256 in a log-only event, and the anti-forgery gate binds every manifest.snapshot_hash to a real tool RESULT event; pure lib/ has zero @deepseek-ai imports and unit-tests standalone
- **Check (run — the gate):** `npm --prefix dsh-academic-search test && bash checks/evidence_materialization_e2e.sh && node checks/antiforgery_probe.mjs --tamper-snapshot --expect-fail --bypass-gateway --expect-fail`  ·  expect: `pass`
- **Falsifiable when:** the e2e run's session jsonl shows a manifest.snapshot_hash with no matching tool RESULT event hash; OR a tampered CAS snapshot still passes the anti-forgery gate; OR content fetched by a direct bash+curl (bypassing the gateway tool, thus no RESULT event) is accepted as evidence — any of these means provenance is not bound to runtime traces (P-10)
- **Passing-but-wrong (ruled out):** the plugin returns real search results but the snapshot bytes are the worker's self-reported extracted_text rather than the tool-executor's fetched bytes (the RT-4 bypass: real fetch + forged extract) — ruled out: antiforgery_probe tampers the extracted_text while leaving the CAS snapshot intact and asserts the gate matches against the门-side CAS extraction, not the worker's text
- **Depends on:** `evidence-contracts`  ·  admit downstream only once this check passes.
- **Stop:** max 6 iterations; failure branches:
    - a top-severity anti-forgery bypass lands inside the previous iteration's own fix (pre-registered stall -&gt; restart, do not patch forward)
    - the fetch fallback chain cannot produce a bound snapshot for the golden source set after 5 iterations
- **On failure:** restart.

### Stage 4 — `research-preset-min`  ·  pattern: plan_execute_verify

- **Done when:** M4 as a MINIMAL single external RESEARCH-ROUND (L1-L5 internal loops at fan-out 1) runs headless on a fixed golden topic and produces runs/&lt;slug&gt;/claims.tsv whose full gate run exits 0, with at least one claim of each kind (data/source/inference) reaching a terminal state (verified-*/contested/unverified) that was written only by the gate, never by the conductor
- **Check (run — the gate):** `dsh --profile academic-research "$(cat checks/golden-topic.txt)" && python3 gates/run.py runs/$(cat runs/LATEST) && node checks/assert_terminal_states.mjs --kinds data,source,inference --writer gate-only`  ·  expect: `pass`
- **Falsifiable when:** the headless run exits non-zero, OR the produced ledger has no claim in some kind, OR assert_terminal_states finds a status transition whose session-event writer is the conductor/worker rather than the gate script — the credibility write-authority (RT-2) leaked
- **Passing-but-wrong (ruled out):** the run produces a ledger where every claim is trivially 'unverified' (the loop did no real grounding) and the gate vacuously passes — ruled out: assert_terminal_states requires ≥1 claim per kind to reach a POSITIVE terminal state (verified-* or contested via a real reproduce/quote/inference gate), not merely the unverified default
- **Depends on:** `academic-search`  ·  admit downstream only once this check passes.
- **Stop:** max 6 iterations; failure branches:
    - 3 consecutive runs produce a ledger with zero positively-verified claims (the loop is not doing real research, only defaulting to unverified)
    - goal-round-driver cannot drive a single round to a gate-passing ledger
- **On failure:** loop back to `academic-search`.

### Stage 5 — `milestone-1-ab`  ·  pattern: review

- **Done when:** MILESTONE 1 (P-15 honest test, gates the expensive scale-up): the held-out eval harness runs BOTH A/B arms to completion — arm A gated-vs-freehand, arm B hyper-parallel-vs-same-budget-serial — on physically isolated held-out tasks, and populates scoreboard.tsv with each success number paired to its integrity counterpart. The GATE is that the A/B ran honestly with paired metrics and burned-task isolation held; the VERDICT (proceed / redesign / honestly report null) is the human's
- **Check (run — the gate):** `node eval/harness.mjs --ab gated:freehand --ab parallel:serial-same-budget --held-out --fail-closed && node checks/scoreboard_integrity.mjs --require-paired-metrics --require-burned-task-isolation`  ·  expect: `pass`
- **Falsifiable when:** the harness cannot complete either arm, OR the scoreboard has a success number with no paired integrity/damage metric (unpaired success = the shape of slop, P-18), OR a held-out task that entered any dev loop is re-scored (isolation broken), OR the two arms differ in a variable other than the one under test (gated-ness / parallelism)
- **Passing-but-wrong (ruled out):** the A/B is tuned until gated+parallel wins (reward-hacking the honest test) — ruled out: the gate does NOT check 'gated wins'; it checks the run completed with paired metrics and isolation intact. A null or negative result (parallel does not beat serial) PASSES this gate and ESCALATES to the human go/no-go, which may honestly stop the project ('do not add more framework to hide it')
- **Depends on:** `research-preset-min`  ·  admit downstream only once this check passes.
- **Stop:** max 3 iterations; failure branches:
    - the held-out eval harness or the isolation checker cannot be made to run to completion (infra broken, not a result)
- **On failure:** escalate.

### Stage 6 — `hardening-scale`  ·  pattern: plan_execute_verify

- **Done when:** ONLY after the human green-lights milestone 1: M5 eval-track fail-closed (eval-of-eval negative tests) + M4 scaled to hyper-parallel multi-loop, proven safe by concurrent-write integrity and the flat hyper-parallel regression curve
- **Check (run — the gate):** `node eval/selftest.mjs --plant confident-but-wrong --expect REVISE --plant missing-panel --expect NOT-SHIP && node checks/concurrent_admission.mjs --grounders 8 --assert-no-corruption && node checks/parallel_regression.mjs --toolcalls 2,20,150 --assert-support-rate-flat`  ·  expect: `pass`
- **Falsifiable when:** a planted confident-but-wrong candidate is NOT forced to REVISE, OR a missing-panel candidate can SHIP (fail-closed broken, TESTING §8), OR 8 concurrent grounders corrupt the ledger (admission serialization broken, RT-18), OR citation-support-rate falls as tool-calls scale 2-&gt;150 (parallelism amplifies sourcing error, TESTING §3)
- **Passing-but-wrong (ruled out):** the parallel regression 'passes' because it never actually reached 150 concurrent tool-calls (fan-out capped silently) — ruled out: parallel_regression asserts the achieved tool-call count reached each target before it judges the support-rate curve
- **Depends on:** `milestone-1-ab`  ·  admit downstream only once this check passes.
- **Stop:** max 6 iterations; failure branches:
    - 2 consecutive iterations fail in the same class (eval-of-eval or concurrent-write)
    - the flat-curve property cannot be met without capping fan-out below the design's parallelism target
- **On failure:** loop back to `evidence-contracts`.

### Stage 7 — `attack-fixaudit`  ·  pattern: review

- **Done when:** M6 house attack battery over the BUILT system (not the docs): seed-verified multi-lens attackers + a cross-vendor attacker find defects; every P1/P2 is adjudicated and fixed; a fresh-context fix-audit (never saw the fixes) confirms the repairs are real and introduced no new contradiction
- **Check (run — the gate):** `node checks/attack_battery.mjs --require-seed-hit --lenses coherence,gaming,evidence,reality,foundation --cross-vendor && node checks/fixaudit.mjs --fresh-context --require-verdict CONVERGED --adjudicated-p1p2-zero-open`  ·  expect: `pass`
- **Falsifiable when:** a lens run misses its planted seed (attacker is blind, run void — not counted), OR any P1/P2 is left open, OR the fresh-context fix-audit returns FIX_FIRST (a repair was cosmetic or introduced a new defect)
- **Passing-but-wrong (ruled out):** the battery reports clean because the attackers were weak (found nothing), read as 'system clean' — ruled out: the seed gate voids any lens run that misses its fingerprinted seed, so 'clean' only counts when the attackers demonstrably CAN find planted defects
- **Depends on:** `hardening-scale`  ·  admit downstream only once this check passes.
- **Stop:** max 4 iterations; failure branches:
    - a P1 lands inside the previous round's own fix (fix-audit rotation stall -&gt; loop back to the implicated module stage, do not patch forward)
    - 3 attack rounds fail to reach CONVERGED
- **On failure:** loop back to `hardening-scale`.

### Stage 8 — `prose-exit-bench`  ·  pattern: retry

- **Done when:** M7 thin prose exit (every empirical sentence cites a claim_id, zero ledger-external assertions) + M8 headless regression batch green with an append-only scoreboard, closing the build
- **Check (run — the gate):** `node checks/prose_exit_closure.mjs --assert-sentences-subset-of-ledger && bash checks/regression_batch.sh --headless --assert-exit-codes && node checks/scoreboard_append_only.mjs`  ·  expect: `pass`
- **Falsifiable when:** the prose exit emits an empirical sentence with no claim_id or an assertion absent from the ledger (ledger-external claim leaked into prose), OR a regression-batch headless run exits non-zero, OR a scoreboard row was deleted/mutated (append-only violated)
- **Passing-but-wrong (ruled out):** the closure check passes because the prose is empty / trivially cites but the citations point at unverified claims presented as settled — ruled out: prose_exit_closure asserts every load-bearing empirical sentence maps to a claim_id AND surfaces that claim's actual state (verified/contested/unverified), never laundering an unverified claim into declarative prose
- **Depends on:** `attack-fixaudit`  ·  admit downstream only once this check passes.
- **Stop:** max 4 iterations; failure branches:
    - the regression batch cannot be made green without weakening a check
- **On failure:** loop back to `attack-fixaudit`.

## Stop conditions (overall)
- **Success:** all eight stages' checks pass in dependency order (skeleton -&gt; evidence-contracts -&gt; academic-search -&gt; research-preset-min -&gt; milestone-1-ab -&gt; hardening-scale -&gt; attack-fixaudit -&gt; prose-exit-bench), the milestone-1 human go/no-go was recorded, and the built profile runs a research task headless producing a gate-passing claim ledger whose prose exit is ledger-closed. Minimum-progress floor: every stage gate must have been reached and attempted with a real diff, and milestone-1-ab must have produced a populated paired-metric scoreboard, before any stop is honoured — a stop below that floor escalates, it does not count as done.
- **Max iterations (budget cap):** 5
- **Failure branches:**
  - any stage exhausts its max_iterations without passing its check
  - a downstream stage forces a redesign of an already-accepted upstream stage twice (error amplification -&gt; escalate the contract, not the build)
  - 2 consecutive outer iterations produce zero new file changes (zero-change gate: the loop is buying iterations, stop)
  - 2 consecutive iterations fail in the same class OR a top-severity defect lands inside the previous iteration's own fix (pre-registered stall -&gt; the stage's on_failure restart fires; do not patch forward)
  - DeepSeek balance floor breached (&lt; the pre-set threshold) — shared budget guard, stop rather than overrun (house precedent)
- **Escalate to a human when:**
  - milestone-1-ab produces a null or negative A/B result (hyper-parallel does not beat same-budget serial, or gated does not beat freehand) — escalate the P-15 go/no-go to the human; honestly report and possibly stop, do NOT tune the A/B until it wins

## Terminal states
- **SUCCESS** — all eight stages' checks pass in dependency order (skeleton -&gt; evidence-contracts -&gt; academic-search -&gt; research-preset-min -&gt; milestone-1-ab -&gt; hardening-scale -&gt; attack-fixaudit -&gt; prose-exit-bench), the milestone-1 human go/no-go was recorded, and the built profile runs a research task headless producing a gate-passing claim ledger whose prose exit is ledger-closed. Minimum-progress floor: every stage gate must have been reached and attempted with a real diff, and milestone-1-ab must have produced a populated paired-metric scoreboard, before any stop is honoured — a stop below that floor escalates, it does not count as done. → done.
- **STOPPED_UNMET** — a max-iteration cap is hit or a failure branch fires: stop, report the last green stage and the unmet gate, hand back the partial diff, do NOT merge. Never relax a gate to force a pass.
- **ESCALATE** — one of the escalate triggers above fires: hand to a human.

## Checker (separate, fresh-context)
- at each stage a fresh adversarial evaluator context (never saw the generator's impl or reasoning) is told the artifact is broken and must prove it — this IS the per-stage attack verification. For the credibility-core stages it runs the house lens battery (coherence/gaming/evidence/reality/foundation) + a cross-vendor attacker; it verifies the gate DISCRIMINATES (would fail on a broken impl), not merely that a green check exists. The conductor owns checks/ and .loop-state/ (generator may not edit them) and commits gates-baseline-&lt;stage&gt; tags so a gate is honoured only when git diff against its baseline tag is empty and the tree is clean.

## Risk guards
- **reward hacking the gates — the system being BUILT is itself a gate-checker, so the generator has an unusually direct incentive to weaken the very credibility gates it implements (the deepest overfitting surface in this build)** → A25 diffs every check against its gates-baseline tag; the fresh adversarial evaluator re-derives whether each gate DISCRIMINATES (red-before-green fixtures); conductor owns checks/ and the generator cannot edit them; attack-fixaudit stage re-attacks the built gates cross-vendor
- **reward hacking the A/B honest test — tuning the loop until gated+parallel wins, defeating the whole P-15 point** → milestone-1-ab's gate checks the A/B RAN with paired metrics + isolation, NOT that gated wins; a null result passes the gate and escalates to a human verdict; the held-out set is physically isolated with a burned-task ledger so it cannot be tuned against
- **error amplification — a wrong evidence-contract (stage 2) silently poisons every downstream credibility judgment** → contract-first with 27 red-before-green fixtures gates stage 2 before anything consumes it; downstream failures loopback to evidence-contracts rather than patching in place; stage 2 carries a restart (not loopback) because a rotted contract is rewritten, not patched
- **context drift / provenance rot over a long multi-stage build — the credibility claims of the build itself decay** → durable .loop-state on disk survives compaction; metrics always recomputed from e2e-session.jsonl; the planner re-reads the frozen docs each stage rather than its own memory; A26 forbids literature-cited thresholds
- **token / budget blowup — the product's hyper-parallelism multiplied across build iterations** → per-stage token caps + the DeepSeek balance floor stop condition (house shared-balance guard); build-time loop is medium (no fan-out) so construction cost is bounded even though the product fans out at runtime
- **premature over-delegation — spinning up the hyper-parallel M4 machinery before the minimal loop is proven** → milestone-1-ab (a MINIMAL single-loop A/B) gates the hardening-scale stage; the expensive multi-loop scale-up only proceeds on a human green-light, faithful to P-15 'prove it before building more framework'

## Run report (emit this when the loop stops)
> Report the outcome honestly — an escalated or capped run is a successful *loop*, just not a successful *task*. **No success/autonomy number is reported without its integrity counterpart beside it**, or an explicit `not measured` tag.
- **Outcome:** success | stopped-unmet (which cap/branch) | escalated (which trigger) · **iterations** · **cost**.
- **Gates green** — paired with a **diff audit for weakened assertions** (tests deleted, expectations hard-coded, a check loosened to pass). A run that passed by weakening a gate is a failed run.
- **Resolved without a human** — paired with **what escaped**: regressions or gaps the checks did not catch.
- **Throughput** (stages/changes landed) — paired with **defect + rollback rate** over the same window.
- **Iterations to acceptance** — read both ways: too high = slow feedback or a wall; **too low = the check was too weak to fail**.
- **Unpaired?** Sampled audit plus a visible `not measured` tag is the honest degradation; silently dropping the integrity line is not. Verify any speed/benefit claim by external timing or a gate, never by the loop's own account of itself.
