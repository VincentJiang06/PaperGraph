# 未随发布收录的调研

本目录是 v2 规划的一手调研语料。其中 **5 份不随本仓库发布**，本文件是那条排除的
公开说明——**排除本身必须可见**，否则读者只会看到一批解析不了的 `[E:]` 指针，
而不知道那是刻意的还是腐掉的。

## 被排除的 5 份

机器读的是下面这个块，**不是**本文件其余部分的散文。
〔为什么单列〕`check_doc_metrics` 原本扫全文的反引号文件名，于是「不在此列」
那句里提到的三份也被算成排除项，语料数从 26 变成 34——
**一段给人读的说明，不该同时充当机器口径。**

```excluded
gt-profile-plugin.md
gt-orchestration.md
gt-evidence-substrate.md
gt-exec-security.md
GROUND-TRUTH-CORRECTIONS.md
```

| 文件 | 内容 |
|---|---|
| `gt-profile-plugin.md` | DSH profile / 插件加载机制的逆向 |
| `gt-orchestration.md` | DSH 编排层（subagent / workflow）的逆向 |
| `gt-evidence-substrate.md` | DSH 工具结果与 `data.meta` 通道的逆向 |
| `gt-exec-security.md` | DSH 执行与权限边界的逆向 |
| `GROUND-TRUTH-CORRECTIONS.md` | 上述四份在实测中被推翻的条目汇总 |

## 为什么

DSH（`@deepseek-ai/dsh`）是 npm 上的公开包，所以**这不是保密问题**。
排除的理由是另一条：**别把别人家包的逆向档案当成自己仓库的内容发布**。

自己项目的考古（`gt-pg-current.md` / `gt-pg-failure.md`）与自己仓库的方法论
（`gt-house-method.md`）**不在此列**，它们照常发布。

## 对读者意味着什么

- 本仓库正文里指向这 5 份的 `[E:]` 指针，在**发布树里解析不了**。
  这是排除的直接代价，不是缺陷。`gates/check_pointers.mjs` 把它们单独计数并打印，
  不与「真的腐掉的指针」混在一起——两者的修法完全不同。
- 这些指针背后的**结论**都已写进正文（01–06 各文档），并且凡是承重的结论
  都另有实测记录在 `.loop/m0/`（可重跑、可对哈希）。
  也就是说：**丢的是出处的原始笔记，不是证据链本身**。
- 需要复核的人可以自己对 DSH 做同样的逆向——`.loop/m0/` 里的每条记录都写明了
  实测命令与预期输出，这本身就是复核的入口。

## 口径

`gates/check_doc_metrics.mjs` 的语料规模按**调研维度**计，不按仓库里存了几个文件计：

```
实测值 = 在场文件数 + 本文件声明排除的份数
```

因此「26 份调研」在发布树（21 份在场 + 5 份声明排除）与开发树（26 份在场）里
是同一个数——**做过的调研**与**发布的文件**本来就是两回事，这行公式把它写死了。
