# 外部调研 v2 · 维度：中文学术与 deep-research 生态

**调研日期：2026-08-17**　**方法：bocha（中文索引）+ WebFetch 一手源 + OpenAlex/Crossref API 实测**
**核验纪律：每个承重数字均记录「口径三元组（什么指标 / 在什么样本或档位上 / 与什么比）」，并标注 verified / corrected / unverified。**

## 结论摘要

1. **国标换版了，而且就在 6 周前生效——这是本维度最高优先级的发现。** `GB/T 7714—2025《信息与文献 参考文献著录规则》` 于 **2025-12-02 发布、2026-07-01 实施**，**GB/T 7714—2015 状态已变为「废止」**（一手：国家标准全文公开系统 openstd.samr.gov.cn）。而中文 Zotero 生态的事实标准仓库 `zotero-chinese/styles`（6.3k star）README 至今仍写「大部分由 GB/T 7714—2015 衍生」。**引文格式的工具链与国家标准之间当前存在一个公开的版本裂口**，本系统若照搬 CSL 即会稳定输出一份已废止标准的格式。

2. **中文文献在国际开放索引中的覆盖是「结构性残缺」，不是「稍微少一点」。** 一手实测（2026-08-17，OpenAlex API）：全库 324,389,590 条中 `language:zh` 仅 5,059,316 条（1.56%）；且**中文年产出在 OpenAlex 中断崖**——2015 年 309,668 条，2023 年仅 30,177 条（为 2015 年的 9.7%）。文献侧（arXiv:2512.16339）以 2023 版北大核心 1,987 种刊为样本：OpenAlex 只收录 **734 种（37%）**、其论文 **24%**。

3. **更致命的是引文关系缺失，它直接杀死 v1 的「引文网络滚雪球」能力。** 论文口径：OpenAlex 中这批中文论文 references 字段完整率仅 **7%**。我方独立随机抽样（`language:zh`，2020–2024，`sample=100&seed=42`）复现出同量级：**refs>0 仅 2/100，机构 institutions 仅 1/100**。

4. **顶刊按 ISSN 查不到——这是比「覆盖率低」更隐蔽的失败模式。** 实测：《管理世界》(1002-5502)、《中国社会科学》(1002-4921)、《历史研究》(0459-1909) 三个 ISSN 在 OpenAlex `sources` 中命中数**均为 0**；改用刊名检索才发现存在**无 ISSN 的残桩记录**（管理世界 1007 篇、历史研究 392 篇），《中国社会科学》中文版根本不存在（只有「英文版」）。同样三个 ISSN 在 Crossref 中**均未注册**。任何以 ISSN/DOI 为主键的中文检索流水线，对最权威的中文期刊会**静默返回空**，而不是报错。

5. **语言字段本身不可信，且存在一个「错代码陷阱」。** 论文口径：1,537,378 条有语言标注的中文刊论文中，仅 **5% 标为中文、92% 标为英文**。实测另发现：`language:zh-cn` 只返回 16,356 条，`language:zh` 才是 5,059,316 条——用错代码会得到一个「看起来正常」的小结果集而非报错。

6. **DeepSeek API 无原生联网搜索——检索通道必须本系统自持。** 一手（api-docs.deepseek.com，2026-08-17）：文档未提供任何内置 web search / grounding；当前模型 ID 为 `deepseek-v4-flash`（DeepSeek-V4-Flash-0731）与 `deepseek-v4-pro`（DeepSeek-V4-Pro-0813）。且 DeepSeek 网页端的「联网搜索」是产品功能而非 API 能力，2026-07-22 还发生过整站不可用。

7. **中文深度检索的公开最好成绩仍然很低，这反向证明了本项目「机器判定 verified/unverified」的架构选择是对的。** BrowseComp-ZH（289 题 / 11 领域）官方榜首为 OpenAI DeepResearch **42.9%**，多数系统低于 10%；通义 DeepResearch 自报 **46.7**。即：中文多跳事实题上，最强系统也错一半以上——默认「未核实」必须是系统的强默认。

8. **中文检索的「虚假独立佐证」比英文严重一个量级。** 本轮实证：查「秘塔AI搜索」12 条结果中 8 条是内容近乎逐字相同的软件下载站；查「知网反垄断罚款」8 家媒体全部复述同一份市场监管总局通稿。**去重必须按上游出处而非按 URL/域名。**

### A. 引文规范：国标已换版，工具链未跟上

- **GB/T 7714—2025 已生效。** 国家标准全文公开系统列示：GB/T 7714-2025《信息与文献 参考文献著录规则》发布 2025-12-02、实施 2026-07-01、状态「现行」；GB/T 7714-2015 状态「废止」；GB/T 7714-2005、GB/T 7714-1987 亦为废止。
  - 一手：https://openstd.samr.gov.cn/bzgk/gb/std_list?p.p2=GB%2FT+7714
- **变更要点（二手，仅供设计参考，未取得标准正文）**：郑州理工职业学院科研外事处摘要称该标准由全国信息与文献标准化技术委员会（TC4）制定，全面替代 2015 版；新增数据库、预印本、数据集等文献类型，引入可选的唯一标识符字段，扩充载体代码（MT/CD/OL/MM 等）。
  - https://www.zzlgxy.net/i/H202604100812000036077.shtml
  - 另有高校编辑部挂出「GBT 7714-2025文献著录规则.pdf」：https://xuebao.ntvu.edu.cn/2026_03/06_18/content-34826.html ；安徽工程大学：https://kjc.ahpu.edu.cn/2026/0529/c6457a271738/page.htm
- **工具链仍停在 2015。** `zotero-chinese/styles`（6.3k star / 940 fork / 1,799 commits，2026-08-17 抓取）README 明确写「其中大部分是由 GB/T 7714—2015 衍生的」，未见 2025 版相关说明或 issue。
  - https://github.com/zotero-chinese/styles
  - 生态中大量同源 fork（tumashu / adlsn / Yingying9963 / Soft-rime / Hua-Kaifang 等）均为同一份 2015 派生物 —— 典型的虚假独立佐证，实为一个上游。
- **已知的长期痛点**：中英混排时「等 / et al.」切换依赖条目 `language` 字段（zh-CN vs en-US）正确填写，否则输出错误。这意味着**条目语言字段必须由本系统自己判定并写入，不能依赖抓取来的元数据**（见 B 节：语言字段错误率 92%）。

### B. 中文文献在国际索引中的覆盖度（含本轮 API 实测）

- **文献侧一手**：Zhang L., Cao Z., Liu J., van Eck N.J.《Beyond openness: Inclusiveness and usability of Chinese scholarly data in OpenAlex》，arXiv:2512.16339（2025-12-18 提交），已刊于 Scientometrics（DOI 10.1007/s11192-026-05664-4）。
  - https://arxiv.org/abs/2512.16339 ｜ PDF 已本地抽取核对
  - 刊级：1,987 种 2023 版北大核心刊中，**734 种（37%）**被 OpenAlex 收录（按 p-ISSN 匹配；6 种无 p-ISSN，人工确认未收录）。
  - 篇级：在两边共有的 734 种刊上，OpenAlex **1,545,929 篇** vs 万方 **6,453,244 篇 = 24%**（1980–2024）。
  - 元数据完整率（分母＝OpenAlex 中的 1,545,929 篇）：DOI 418,811 = **27%**；References 104,708 = **7%**；Institutions **44%**；Affiliation strings **68%**；Volume/Issue 各 **36%**；首页 35%／末页 33%；Authors 99%；Grants ≈0%（624 条）。
  - 语言字段：有语言标注的 1,537,378 篇中**仅 5% 标为中文、92% 标为英文**，另有少量被标为韩语/越南语/丹麦语。论文注明该问题「此后已有改善（Demes, 2025）」。
  - DOI 生态根因：中国仅 **ISTIC&万方** 与 **CNKI** 两家为中文期刊提供 DOI 注册；注册元数据字段远少于 Crossref（不含关键词、摘要、参考文献），且「两家均不像 Crossref/DataCite 那样提供快照或 API」。
- **另一独立研究**：Zheng M., Miao L., Bu Y., Larivière V.《Understanding discrepancies in the coverage of OpenAlex: the case of China》，arXiv:2507.19302（2025-07-25），已刊于 JASIST（10.1002/asi.70013）。摘要层面结论一致：OpenAlex 对中国论文的覆盖「不完整且不连续」，主要来自某个国家级数据库。
  - https://arxiv.org/abs/2507.19302 ｜ https://asistdl.onlinelibrary.wiley.com/doi/10.1002/asi.70013
- **本轮 OpenAlex API 实测（2026-08-17，可复跑）**：

  ```bash
  curl -s "https://api.openalex.org/works?filter=language:zh&per-page=1"        # 5,059,316
  curl -s "https://api.openalex.org/works?filter=language:zh-cn&per-page=1"     # 16,356  ← 错代码陷阱
  curl -s "https://api.openalex.org/works?filter=language:en&per-page=1"        # 221,037,818
  curl -s "https://api.openalex.org/works?per-page=1"                           # 324,389,590（全库）
  # 逐年：2015=309,668 / 2020=49,120 / 2023=30,177 / 2024=43,972 / 2025=50,146
  curl -s "https://api.openalex.org/sources?filter=issn:1002-5502"              # 0（《管理世界》）
  curl -s "https://api.openalex.org/sources?search=管理世界"                     # 命中无 ISSN 残桩，works_count=1007
  ```

  - **随机抽样（`sample=100&seed=42`，`language:zh`，2020-01-01～2024-12-31）**：DOI 70%、**refs>0 仅 2%**、abstract 64%、**institutions 仅 1%**、volume 61%、authors 96%、is_oa 55%。
  - **⚠ 本轮自查到的一次口径陷阱（值得写进方法论）**：同一条件下若用默认排序取前 50 条，得到 DOI 46/50、refs 25/50 —— 与随机抽样差 1–2 个数量级。OpenAlex 默认排序偏向高被引/元数据齐全记录，**默认分页 ≠ 随机样本**。本报告采用随机样本口径。
- **Crossref 侧实测**：`api.crossref.org/journals/{1002-5502|1002-4921|0459-1909}` 三者**均返回 not found**，即中文旗舰刊未在 Crossref 注册 —— 与上文「中国 DOI 注册机构不走 Crossref」互为印证。
- Crossref 按中文题名可检索（`query.bibliographic=人工智能` 返回 369,859 条），但语言字段同样常为 null，且大量为 book-chapter 类型，**不能作为中文期刊论文的权威索引**。

### D. 国内 deep research 产品的当前形态与引用做法

- **通义 DeepResearch**（阿里，2025-09-17 开源）：`Tongyi-DeepResearch-30B-A3B`，30.5B 总参 / 3.3B 激活，128K 上下文，Apache-2.0。技术报告 arXiv:2510.24701（2025-10-28）自报成绩见核验表。
  - https://github.com/Alibaba-NLP/DeepResearch ｜ https://arxiv.org/abs/2510.24701
  - **对本项目的价值**：这是目前唯一一个把中文深度检索能力开源+可自托管的选项，可作为「第二意见评估器」的候选，但其分数为自报。
- **Kimi 探索版**（月之暗面，2024-10-11 发布）：主打自主搜索，宣称搜索量为普通版 10 倍（厂商口径，二手转载）。
- **豆包 / DeepSeek / 元宝**：BrowseComp-ZH 官方榜中均以「AI 搜索产品」身份被测（豆包深度搜索 26.0%、DeepSeek 深度思考 7.6%、元宝 12.2%、Kimi 深度思考 8.0%）。

- 国内横评类文章（cnblogs/CSDN/aitoolcn 等 2026 年「大模型横评」）**全部为营销/SEO 稿，无可验证方法学**，本报告不采信其任何数字。

### G. 中文全文获取与解析

- **无合法可编程全文通道**：知网/万方/维普全文均为机构订阅 + 反爬；爬取行为在国内存在明确刑事/民事风险（《刑法》285 条相关判例与学理讨论广泛存在）。**本系统不得设计任何绕过订阅墙的抓取路径。**
- 可用免费全文通道：NCPSSD（社科，免费下载）、ChinaXiv（预印本）、期刊官网 OA、维普 OA 平台；NSTL 提供文献传递（人工、非实时）。
- **PDF 解析**：MinerU（OpenDataLab 开源）是当前中文版式 PDF → Markdown/JSON 的主流开源方案，支持文本/图/表/公式抽取。→ 用户自备 PDF 时的解析层首选。
  - https://github.com/opendatalab/MinerU （本轮经多个中文技术页转引确认其定位，未逐项核验其准确率指标）

## 对本项目的设计含义

### 1. 检索通道：必须自持，且必须双通道按语言路由
- DeepSeek API 无原生搜索（verified），检索层 100% 由本系统负责，不存在"靠模型自带联网"的退路。
- bocha（中文索引）与 serper（Google 系）**索引重叠极小**——本轮同一主题在两边得到几乎不相交的结果集。**按「断言的语言/属地」路由，而非按用户界面语言**：中文政策、统计、国内机构走 bocha；国际论文、英文一手文档走 serper。
- bocha 的工程约束（已在本轮实测中确认）：单次上限 50 条、**完全忽略分页**（第 1/2/3 页返回相同结果集）。→ **扩大召回只能靠"多角度并行查询"，不能靠翻页**。这直接决定 fan-out 形状：一个中文检索子任务应一次派发 3–6 个不同措辞的查询，而不是一个查询翻 5 页。

### 2. 证据分级必须新增「获取层级」维度（v1 缺失）
中文场景下"拿到全文"经常不可能。证据卡除了 verified/unverified，必须再带一个**获取层级**：
- `L3 全文`（用户提供 PDF / OA 全文 / NCPSSD / ChinaXiv）→ 可支持"引文可溯源到原文句子"
- `L2 摘要`（OpenAlex/万方/维普摘要）→ 只能支持结论级引用，**禁止声称核对过原文**
- `L1 题录`（仅题名/作者/年）→ 仅能作为存在性证据，**不得用于支撑任何数值断言**
没有这一层，系统会把"我看到了标题"伪装成"我核对了结论"——这正是本项目要消灭的失败模式。

### 3. 引文格式：必须自持格式化器 + 标准版本显式锁定
- **不得依赖 Zotero CSL 作为正确性来源**：现行国标已是 GB/T 7714—2025（2026-07-01 实施），而 CSL 生态仍是 2015 派生物。
- 每个写作任务必须**显式 pin 一个标准版本**（`gbt7714-2025` / `gbt7714-2015` / 院校自定义模板），因为**高校模板换版滞后是常态**——学生的实际要求很可能仍是 2015 版。默认值应为「询问 / 从模板推断」，不是硬编码最新版。
- 条目的 `language` 字段必须**由本系统按题名字形判定后写入**，不能采信抓取来源（OpenAlex 语言字段 92% 错误）。这决定「等 / et al.」是否正确。

### 4. 引文网络能力在中文场景「基本失效」——v1 能力退化清单
| v1 能力 | 中文场景下的状态 | 处置 |
|---|---|---|
| 按 DOI 精确定位文献 | **严重退化**：中文刊 DOI 完整率 27%，旗舰刊未在 Crossref 注册 | 降级为「题名+刊名+年+期」复合键匹配（照抄论文的 5 级匹配规则） |
| 引文滚雪球 / 参考文献回溯 | **基本失效**：refs 完整率 7%（论文口径）/ 2%（随机抽样） | 中文任务**关闭**该策略；改为主题词多角度扩展 + 综述类文章人工提取 |
| 按 ISSN 锁定期刊、限定检索范围 | **对顶刊失效**：三大旗舰刊 ISSN 命中 0 | 改为刊名匹配 + 本地维护「刊名→分级」映射表，不依赖 OpenAlex sources |
| 按 `language` 字段筛选中文文献 | **失效**：92% 错标 | 改为对题名做字形检测（CJK 比例） |
| 机构/作者消歧 | **严重退化**：institutions 完整率 44%（论文）/ 1%（随机抽样） | 中文任务不做机构级聚合分析 |
| 「同一结论多源独立佐证」 | **高危误判**：中文网页池同源转载极重 | 去重键改为**上游出处**（通稿来源/原始发布机构），而非 URL/域名 |

### 5. 可信度分层规则（可直接编码）
- 硬性 T0：`*.gov.cn` 统计公报/年鉴/公示 > 一切二手转述。
- 期刊分级查表：北大核心 2023 版（1,987 种）/ CSSCI 2025-2026 / CSCD / 科协 T1-T3 —— **这些名录需作为本地静态资源随插件分发并标注版本日期**，不能每次联网查（各高校转载页彼此矛盾，见核验表）。
- 预印本（ChinaXiv）自动降一级并强制标注「未经同行评议」。
- **硬黑名单**（本轮实证必要性）：软件下载站、文库/道客巴巴类二次上传、内容农场、无方法学的"大模型横评"SEO 稿。本轮查「秘塔」12 条里 8 条是下载站——不做域名过滤，中文检索的信噪比无法接受。

### 6. 「机器判定 verified/unverified」的默认值应偏保守
BrowseComp-ZH 最强系统 42.9%、xbench 多数智能体 30–40 分——**中文多跳事实题上，业界最好水平仍错一半以上**。因此：
- 默认状态是 `unverified`，需要证据主动把它推到 `verified`，而不是相反。
- 中文数值型断言（统计数字、金额、占比）必须要求 T0/T1 源 + 获取层级 ≥ L2，否则一律 unverified。
- 系统应把「口径三元组」作为证据卡的**必填字段**——本轮自查抓到的抽样偏倚（默认排序 vs 随机抽样，差 1–2 个数量级）证明即使数据来自权威 API，口径错了照样得到错误结论。

### 7. 可复用的自检资产
本轮的 OpenAlex/Crossref 实测命令是**可复跑的**，建议直接固化为插件的「中文检索通道健康检查」：定期跑一次，若 `language:zh` 年产出、refs 完整率等指标变化，说明上游生态改善，可重新开启已关闭的能力（如引文滚雪球）。

## 未决与风险

1. **GB/T 7714-2025 标准正文未取得**。变更清单来自一所职业学院的摘要页，未经标准原文核对；国家标准全文公开系统对该条目未提供免费全文。**风险**：若据此实现格式化器，可能格式细节出错。→ 建议实现前购买/获取标准正文，或先仅支持 2015 版并明示。
2. **知网开放平台条款与价格未取得**（open.cnki.net 返回 503）。是否真的对个人/小团队开放、价格如何，全部未知。**在确认前，架构不得假设存在任何知网可编程通道。**
3. **博查 / 秘塔 / 阿里 IQS 的 API 单价全部未取得**（价格页需登录）。成本模型中的中文检索单价目前是空的。→ 需用户在已登录环境下补一次，或按调用量实测反推。**特别注意本任务的既定教训：中文云服务极常见"限时优惠价"，取到价格后必须分辨促销价与刊例价。**
4. **「Kimi K3 91.20」这类数字会持续出现在中文 AI 摘要里**。本轮已剔除一次。→ 建议把「榜单类数字必须回到官方 leaderboard 仓库/官网」写成硬规则。
5. **NCPSSD 的规模与是否有 API 未确认**；若其存在批量接口，中文社科的证据获取难度会显著下降，值得单独花一轮确认。
6. **万方作为分母的利益相关性**：37%/24% 两个核心数字的基准由一位万方员工参与选定。目前没有第二个独立基准（如以 CNKI 或知网为分母）的同类研究可交叉验证。→ 引用时必须带"以万方为基准"。
7. **arXiv:2507.19302 的具体数字未取得**（摘要页无数值，未下载全文）。此前 WebSearch 摘要给出的「2003–2011 约 60–70%、2014 降至 34.7%、2016 接近零」**未回到一手，未写入本报告**。但该趋势与我方实测的年度断崖（2015→2023 降至 9.7%）方向一致，值得补一轮核实——**若属实，它解释了断崖的机制（CNKI 停止向 OpenAlex 供数）**，对判断"这个缺口会不会自己修复"很关键。
8. **UHGEval 等中文幻觉基准未取得一手**，中文场景下"引用忠实度"的可测量性尚无结论。
9. **本轮 bocha 的中文结果池质量整体偏低**，部分查询（如 "BrowseComp-ZH 榜单"）返回的是魔方比赛、足球联赛等完全无关内容。→ 说明 bocha 对**英文技术专名 + 中文语境**的混合查询表现差。设计上：技术专名类查询应走 serper，bocha 用于纯中文语义查询。
